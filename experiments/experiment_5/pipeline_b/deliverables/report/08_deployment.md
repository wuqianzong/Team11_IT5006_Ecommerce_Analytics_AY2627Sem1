## 8 Deployment and dashboard

The released models predict exactly what was tested, and the dashboard shows only stored results, each labelled with the model that produced it.

**Release package.** For each task, the improved pipeline's frozen model and the baseline's (as fallback) are packaged with their feature schemas, training profiles and checksums. Reloaded from disk, they re-predict the saved test predictions exactly (largest difference {{B10.reg.parity_max}} for lead time and {{B10.clf.parity_max}} for the alert), from test rows rebuilt with every label column emptied, so no label is read.

**Serving rule.** A router sends each order to the improved pipeline when its customer and seller are both in the seven states and its distance is known, and to the baseline otherwise ({{B10.clf.test_rows_inside}} and {{B10.clf.test_rows_outside}} of the alert's test orders). Every prediction carries a badge naming the model and, outside the seven states, the reason. Inside the seven states, an order not yet handed over gets no alert score; the missed-dispatch rule flags it if its shipping limit passes.

**Input checks.** Unknown states, impossible distances, orders without items and missing instalments are rejected with a clear message. Missing values, unseen categories and numeric inputs more than 4 standard deviations from the training mean are accepted with a warning.

**Dashboard.** A Streamlit app with three tabs: a business overview of all orders (descriptive, labelled as a separate scope from the model results), delivery lead time and detractor risk at handover. The model tabs read only stored outputs and score held-out historical orders. The alert tab's threshold slider moves the improved pipeline's threshold over the stored options (default 4/15) and shows alerts per day, precision, recall and cost; the baseline's fallback stays at its frozen 1/6.

**Using the app.** The app lives in `deliverables/dashboard/app/` with its own environment (Python 3.12 and the package versions pinned in its requirements file, which load the frozen models unchanged). Running `streamlit run app.py` from that folder opens it at `http://localhost:8501`; the README there gives the exact commands. The sidebar names the stored outputs each tab reads and states that no model is fitted and no test label is read. On the detractor tab, a radio button switches the alert statistics between validation (the selection view) and the test (a post-test view), and the slider moves the improved pipeline's threshold, starting at 4/15. The score panels take one held-out order, or a file of held-out orders, and return the prediction with its model badge. The app's tests check the file loaders and the router, that every slider position is a stored threshold, and that the forbidden scope and threshold wording is absent. Screenshots of each tab, the threshold slider at 4/15 and the score panel are stored with the app; the hosted address will be added here once hosting is confirmed.

Data, joins and leakage

Nine tables become one row per order

Aggregate first: items, payments and reviews have several rows per order; each is reduced to the order, then joined one to one

Primary item: the highest-priced; gives the category and the seller

Customers matched on customer_unique_id, so one customer stays on one side of every split

Leakage rule: a column is a predictor only if it exists at the prediction moment; delivery, carrier and review fields never are; Olist’s estimated date is never used

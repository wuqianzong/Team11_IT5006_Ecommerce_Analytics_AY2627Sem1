Aggregate first

Primary item

Customers

Leakage rule

Team 11 · IT5006 · 3/15 · Report section 3 · join diagram from Pipeline A’s data stage (B-G-13)

0:35. Olist ships nine tables. Items, payments and reviews have several rows per order, so each is reduced to one row per order before the join, and the join stays one to one. Customers are matched on customer_unique_id, so the same person never sits on both sides of a split. The leakage rule: a column is a predictor only if it exists at the prediction moment. Delivery, carrier and review fields never are.
